# Trip planning and execution guidance

- Validate before work. Keep trip facts, packing recommendations, execution actions, and physical inventory as separate layers.
- Planning: interview only for missing context, use deterministic matches as candidates, and save all nine recommendation sections with reasons.
- Execution: require a confirmed packing plan and explicit user confirmation for every action that writes state. Never infer that a planned decision happened.
- Record actual `packed`, `used`, `unused`, `rejected`, `transferred`, `purchased`, `damaged`, `discarded`, `lost`, `returned`, or `stayed` outcomes in the execution ledger. Location changes must use exact physical IDs, expected sources, and destinations.
- Preserve preferred locations unless the user separately requests a preferred-home change. A plan or confirmed plan never moves possessions.
- Before completion, review all reconciliation topics: returns, destination stays, unused items, purchases, incidents, and rejected/changed recommendations. Completion is forbidden until every topic is acknowledged.
- Use execution history as future planning evidence. Prior plans are recommendations; only applied execution actions and movement history are factual outcomes.
